SaveLoadScreen (mod-owned, mirrors `CommonVM.SaveLoadVM`). Audited vs decompiled game + WrathAccess.

**Root cause of "Load loads a save I didn't select":** the game's own gamepad view selects a slot ON FOCUS (`SaveSlotConsoleView.SetFocus → SetSelectedFromView`), but selecting only on Enter left `SelectedSaveSlot` at the auto-picked newest save while the cursor moved; Load/Delete act on `SelectedSaveSlot`, not the cursor. Same trap hit Delete + overwrite.
**Root cause of "selection sound on every arrow":** driving the game's selection on focus (`SetSelectedFromView`) flips `SelectionGroupEntityView.OnChangeSelectedState → SetActiveLayer("Selected")` = a select CHIME per slot. Browsing must be silent → don't drive game selection on focus at all.

**DESIGN — COLLAPSIBLE TREE, node-centric** (both root causes gone by construction). The game's own save list is natively a collapsible tree (`SaveSlotGroupVM` has an `ExpandableTitleVM`; the game default-collapses all groups but the FIRST via `IsFirst`) — we mirror it instead of flattening. Structure: a structural root `TreeGroup` → one `TreeGroup` per playthrough (`SaveSlotGroups`, keyed by GameId) → `ProxySelectionItem` save nodes. First playthrough `.Expand()`-ed, rest collapsed. Left/Right fold a run; Down/Up walk saves. **Node-centric verbs (matches loot/inventory idiom, ELIMINATES `_cursorSlot`+Save/Load/Delete buttons):** Enter on a save = `s.SaveOrLoad()` (self-gates load vs overwrite by mode/type); Backspace on a save = `s.Delete()`; Backspace on a playthrough node = `group.ExpandableTitleVM.DeleteAll()` (the game's confirming delete-all); Space = required-DLC names. Acting on the FOCUSED node directly means no "selected slot" to drift, and browsing never touches game selection (silent). Tab-stops: mode selector (dual-mode), New save (save mode; not a slot), then the tree.
- `ProxySelectionItem`: role **"item"** (suppresses the SelectedAnnouncement — a save is acted on, not selected; also stops the descent's `ReportsSelected` from yanking initial focus onto the game's auto-selected slot), plus `onContext`/`contextLabel` (a Backspace secondary action, independent of Availability). Save label = `SlotBrowseLabel` (name, type, saved-date, location, playtime, description joined — mirrors the card; character omitted since the parent group node says it). `g.IsExpanded.Value=true` still set on all game groups (keeps slots Available/actionable in the game VM; independent of OUR fold state).
- `TreeGroup`: settable `ContextAction`/`ContextLabel` + a `GetActions` override (Backspace verb on a group header, e.g. delete-all). Right/Left own expand/collapse.

**SlotType** (from the older model, survives into the tree's SlotBrowseLabel): IronMan-first branch; "cannot load" for current IronMan; ", DLC required" any kind. Marks now localized "Autosave/Quicksave/Manual" via keys. The generic `OnFocusEnter()`/`Navigator.PumpFocus()` framework hooks (Main.cs per-frame, FocusMode-gated) REMAIN but are now unused by saves.

**New-save NAMING:** the game's inline NewSaveSlot field is NOT mounted under our screen (probe: 0 active TMP_InputFields even though SaveLoadPCView is active) — so driving it via TextEntry does NOT work. Instead `NewSave()` raises the game's TextField MessageBox (`EventBus.RaiseEvent<IDialogMessageBoxUIHandler>(HandleOpen(..., BoxType.TextField, ..., onTextResult: name=>{TrySetSaveName; SaveOrLoad}, inputText: default))`) — a TextField box reliably creates exactly ONE active TMP field. **MessageBoxScreen** surfaces TextField boxes: adds an Edit affordance that FindInputField(match InputText)→`TextEntry.Begin`; Accept forwards InputText via OnAcceptPressed→m_TextClose. Also fixes overwrite-rename for free (overwrite already raises a TextField box).

**Feature set:**
- **Delete-all-for-character:** Backspace (Context) on the playthrough's TREE NODE → `group.ExpandableTitleVM.DeleteAll()`, the game's OWN confirming method ("delete character, can't be undone", accept="Delete character"). This is where the game itself puts it (the ExpandableTitle).
- **Updating cue:** `OnUpdate` announces `Loc.T("save.updating")` = "Loading saves…" (queued, FocusMode-gated) on the RISING edge of `vm.SaveListUpdating.Value`. Fires on open (list loads async).
- **Same-name-playthrough disambiguator:** `AmbiguousGroupNames` counts `GroupLabel` collisions across rendered groups; `GroupDisplayName` suffixes ", most recent {date}" (newest SystemSaveTime) ONLY for colliding names. Single-group case → plain name.
- **Required-DLC names on Space:** `ProxySelectionItem` gained `Func<string> detail` → overrides `GetTooltipText()` (plain-text Space body, distinct from the game-template `GetTooltipTemplate`). `DlcDetail(s)` returns null unless `ShowDlcRequiredLabel`, else flattens `DlcRequiredMap` (List<List<string>>) to distinct names → "Requires downloadable content: {dlc}". Card still shows only "DLC required" (SlotType) per the mirror rule.
- **Localization:** the `save.*` ui.json block is fully wired (mode/actions/columns/marks/group.default) + keys save.ironman[_current], save.type_dlc, save.unnamed, save.name_prompt, save.updating, save.delete_all, save.requires_dlc[_unknown], save.group_disambig, screen.saveload.

**Harness gotchas:** (1) `/loadsave` (and the game) HANG on a loading screen waiting for "press any key" — `LoadingScreenVM.NeedUserInput`. Dismiss via `EventBus.RaiseEvent<Kingmaker.PubSubSystem.IContinueLoadingHandler>(h => h.HandleContinueLoading())`. (2) `CommonVM.HandleOpen` (all message boxes) NO-OPS while `RootUIContext.Instance.IsLoadingScreen` (= `LoadingScreenRootVM.LoadingScreenVM.Value != null`) — so confirm dialogs silently fail to open if the game is still on the loading screen; ensure interactive first. (3) `/eval` throws CS0584 on inline ternary-in-string-concat — pre-compute into locals with if/else ([[rt-dev-harness]]). (4) `IDialogMessageBoxUIHandler`/`IContinueLoadingHandler` live in `Kingmaker.PubSubSystem`, not the MessageBox VM namespace. (5) Open the Load window via `CommonVM.HandleOpenSaveLoad(SaveLoadMode.Load, singleMode:false)`; collection populates ~1 frame async. `SaveSlotCollectionVM.SaveSlotGroups` is private (publicize helps mod compile only, NOT the eval compiler) — use public `AllTitlesAndSlots` in eval.
