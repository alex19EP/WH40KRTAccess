RTAccess has a DEBUG-only loopback HTTP dev server (`RTAccess/Dev/{DevServer,DevHttpServer,CSharpEvaluator,DevApi,SpeechTap}.cs`, all `#if DEBUG`) on **port 8772**, gated by a marker file at
`%USERPROFILE%\AppData\LocalLow\Owlcat Games\Warhammer 40000 Rogue Trader\RTAccess\devserver.enable`
(marker survives Steam relaunch; an env var would not). `Mono.CSharp 4.0.0.143` is a Debug-only NuGet `PackageReference`; copy-local + the wildcard Deploy carry it into the UMM folder. Release builds compile all of this out. Part of the [[ui-paradigm-pivot]].

**Dev loop:** `scripts/dev-game.ps1` + the **`/dev-game`** skill wrap close → build → launch → verify. Actions: `cycle` (default, rebuild+rerun), `run`, `build`, `restart`, `kill`, `status`. The game MUST be closed before building (a running game locks `RTAccess.dll`), so the script always kills first. Launch = `steam://rungameid/2186680`. Game process name = `WH40KRT`.

**Endpoints:** `POST /eval` (main-thread C# REPL; bare `DevApi`/`Speaker`/`RTAccess.*` resolve via seeded usings), `GET /speech?since=N` (ring buffer of spoken lines via `Speaker.Observer`), `GET /screenshot` (framebuffer PNG — writes to `%TEMP%\rt_shot.png` and returns that path; Read the path, not the HTTP body), `POST /loadsave` (body `latest|quick|<idx>`, blocks until in-play), `GET /health` (answers on the HTTP thread even mid-load), `/gui` (lists screen buttons), `/input <action>` (injects a registered action by key — mode-independent, the reliable way to drive nav without raw keys). `/eval` needs the Pump (main thread).

**Namespace gotcha:** the `RTAccess.Input` namespace shadows `UnityEngine.Input` for legacy bare `Input.GetKey*` code (qualify those); `CountingGuard.dll` needs an explicit csproj reference.

**In-world test routine (get a clean surface state for testing service windows):** `/loadsave` drives the load but LEAVES the game on the post-load **"press any key" screen** (`LoadingProcess.IsAwaitingUserInput` / `LoadingScreenVM.NeedUserInput`); driving menu Continue hits the same screen. The harness `/input` can't dismiss it (the prompt reads RAW Unity input, not the FocusMode-suppressed `KeyboardAccess`) — you must send a real key: foreground the window (`SetForegroundWindow` via P/Invoke; Steam may background it) then `keybd_event` VK_SPACE. Then a startup **DLC notification MessageBox** appears — **DECLINE it** (`MessageBoxVM.Value.OnDeclinePressed()`); ACCEPTING opens the DlcModManager full-screen UI which sets `FullScreenUIType=DlcModManager` → `IsBlockedFullScreenUIType()` true → service windows refuse to open (`ServiceWindowsVM.HandleOpenWindow` early-returns). After that you're clean; open a window via `ServiceWindowsVM.HandleOpenWindowOfType(type)` or `EventBus.RaiseEvent<IEscMenuHandler>(h=>h.HandleOpen())` for the Esc menu. **FocusMode trap:** a full-screen UI the mod doesn't own can't be closed with FocusMode on (game Escape is suppressed) — toggle FocusMode off (`/input toggle_focus`), send raw Escape, toggle back. Combat events can be tested synthetically: `EventBus.RaiseEvent<IUnitDeathHandler>(h=>h.HandleUnitDeath(unit))` / `IWarningNotificationUIHandler`.

**`/eval` REPL QUIRKS (Mono.CSharp `Evaluator`):** the REPL is **C# 6.0** — no pattern matching (`x is T y` → CS1644), no tuples/`Array.Empty` idioms; use `as`+null-check and explicit types (avoid `var` at statement position, it sometimes parses as an identifier). It consumes one statement at a time; a **multi-statement block does NOT return the trailing expression's value** (you get `(ok)`), and a bare single expression that spans/has a trailing newline can read as "incomplete" → also `(ok)`. **Robust pattern: end with `System.Console.WriteLine(...)`** — the harness captures `Console.Out` and returns it regardless of `result_set`. Post the body via `curl.exe --data "@file"` (write the C# to a scratch `.cs` first) to dodge PowerShell quoting of `$"`/`\"`; a lone expression like `2+2` returns `=> 4`. **`using` directives must be sent as their own `/eval` first** (no using-directives mid-block). An inline **ternary-in-string-concat (or any ternary/lambda inside a block) can throw CS0584** "internal compiler error: not implemented" — pre-compute into locals with if/else. An **empty response / curl exit 56 is NOT the snippet's fault** — it is the loopback reset described below (an earlier note blamed `continue` inside loops for it; that was this reset misdiagnosed). Every `Eval` path returns text (`[compile]`, `[exception]`, `=> v`, `(ok)`), and the main-thread job usually ran anyway, so retry over `localhost` before restructuring code.

**Loopback resets (measured 2026-09-11):** on the dev box a filter driver (AdGuard VPN / Tailscale are installed) turns IPv4 loopback teardown into a RST often enough that a standalone CLR listener lost 10–15 of 40 replies over `127.0.0.1` (HTTP; ~2/40 for a raw payload), while `::1` was clean 0/80 — same client, same code. Not Mono, not the server's code. Fixes shipped: `DevHttpServer` binds **both** `127.0.0.1` and `[::1]` as two sockets (never a dual-mode `::` — exposes every interface, and Windows defaults IPV6_V6ONLY on) and half-closes + drains until the client closes before `Close()` (cuts the v4 loss to ~3%); `dev-game.ps1` / the skill / CLAUDE.md address **`localhost:8772`**, which Windows resolves to `::1` first. Verify after a rebuild with a 30× `GET /health` loop (`probe2.ps1`-style raw `TcpClient`, `-HostAddr ::1`).

**Synthetic raw keys via `keybd_event`:** the EXTENDED keys (PageUp/Dn `0x21/0x22`, Home/End `0x24/0x23`, Insert/Del, arrows) need the `KEYEVENTF_EXTENDEDKEY` flag (`0x0001`) on BOTH down and up (up = `0x0003`) or Unity's `Input.GetKeyDown` never sees them — letter/punctuation keys work without it. To drive a raw-key feature gated on `!Navigation.HasFocus`, call `RTAccess.UI.Navigation.Blur()` over `/eval` first, foreground the window with `(New-Object -ComObject WScript.Shell).AppActivate($pid)` (more reliable than `SetForegroundWindow`), then send keys. To bypass key delivery entirely, invoke a private handler over `/eval` via `System.Type.GetType("RTAccess.X.Y, RTAccess").GetMethod(name, NonPublic|Static).Invoke(...)` — `typeof()` fails on `internal` types from the eval's separate assembly, `Type.GetType` works.
