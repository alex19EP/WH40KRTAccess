The game's TB movement simulation is NOT the ghost — it's one write: `Game.Instance.VirtualPositionController.VirtualPosition = cell` (raises `IVirtualPositionUIHandler`); every readout (cover overtips, LOS-line VMs, hit chances, ability range, action-bar slots) calls `GetDesiredPosition(entity)` which substitutes it iff entity == acting turn unit, in player party, no running command. Self-clears on all turn transitions. The full two-click flow: `TryCreateMoveCommandTB(…, showMovePrediction: true)` queues a `DrawMovePredictionGameCommand` that BOTH draws the prediction (path + walking hologram via `DrawMovePredictionLocal`/`SetMovementHologramPosition`, pinning the virtual position) AND memorizes the command via `UnitCommandsRunner.SetVirtualMoveCommand` (also wires Esc-cancel); a same-destination re-call returns `SamePath` → `TryRunVirtualMoveCommand()` runs the pinned move. Plant lands a frame late (GameCommandQueue). Hover yields to a pinned hologram (`m_VirtualHologramPosition`) — game precedence.

**Why:** Mod design (2026-07-12, replaced the earlier Ctrl-force + speech variant — user dropped both): (1) `HoloSim.Tick` silently auto-sims the tile cursor inside the movable area (no announcements — "ambient lens, not an event"); when a hologram is pinned it hands ownership over WITHOUT cleaning (cleaning would kill the plan's anchor since the pin often holds the same value). (2) `CommandDispatch.MoveStep` (generalized from ShipMoveStep — identical for walkers + ships, plus the game's walker `CanUnitStandOnNode` pre-check) is the Backspace two-step in TileExplorer.MoveToCursor: first press plants the holo unit + speaks PathInfo preview, second press on the same tile commits; fresh arm always `MoveCancelLocal()` first so a lapsed window can't instant-commit.

**How to apply:** Never build "if I stood here" reads by hand — engage the sim and let the game's own math answer (scanner per-enemy cover/range/threat + action-bar availability already ride it via `GetDesiredPosition`). Shipped on top (2026-07-12): `CombatReads.LosHitChance` ports `LineOfSightVM.UpdateHitChance` (ranged-preferred weapon, reticle cache from best shooting position, scatter via oriented pattern, flat cover map 80/50/10/0 with no ability; NO line for melee/charge — return −1; hidden at 0) — spoken in the scanner enemy suffix + the vantage key's `LosSweep` fan (LOS lines exist only acting-unit→enemies and only while hover/aim/AoE/virtual-position — browse = hover, so parity holds). Path preview names hazard zones over the parent-chain path (`ProxyAreaEffect.IsHazard`, fog-gated, origin skipped, "crosses" vs "ends in") — the game paints zones but never marks the path line. **GOTCHA (2026-07-12 fix): area-effect cell membership is `ae.CoveredNodes.Contains(node)` — the quantized pattern the HUD paints and `RuleCalculatePassedAreaEffects` tests — NEVER `ae.Contains(node)`, the raw metre-radius shape that overhangs the painted cells (3 m radius paints ⌊3/1.35⌋=2 cells) and yields rim false positives.** Backspace plant/commit is STATELESS (second fix same day): no local arm/timeout — the engine's SamePath detection IS the confirm (a 3 s confirm window silently un-armed and forced re-plants); the pin persists until commit / Esc / turn end.
